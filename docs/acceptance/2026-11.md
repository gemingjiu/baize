## 走查中发现的缺陷与处置

1. **登录日志 msg 溢出（真实缺陷，已修复并回归验证）**：首次空体登录 `POST /auth/login {}` 触发 system 侧 `ERROR: value too long for type character varying(255)`（`SysLoginLogMapper.insert`）。根因：`AuthController.login()` 的 catch 把完整 `e.getMessage()`（含 Feign 异常响应体，约 400 字符）经 `recordLoginLog` 写入 `sys_login_log.msg`（varchar(255)）。修复：`AuthController` 新增 `LOG_MSG_MAX_LENGTH=255` 与 `truncate()`，写日志前统一截断。重新打包 baize-auth 通过（`BUILD_SUCCESS`），重启后重放空体登录：新日志 `value too long` 出现 0 次，DB 查询确认落库 `msg_len=255`（恰好截断到上限），成功登录日志 `msg_len=4`（"登录成功"）。回归通过。
2. **"用户不存在" 为假阳性（非缺陷）**：`GET /api/v1/system/user/list` 命中 `@GetMapping("/{id}")`（把 "list" 当 id），system 日志 `Parameters: list(String)` → 0 行 → `NotFoundException("用户不存在")`。真实分页接口是 `POST /system/user/page`（`SysUserController.java:132-140`），前端列表走此接口，功能正常。
3. **直连 system 报 30002 / 租户缺失告警**：均为设计内——前者是"拒绝绕过网关直连后端"的签名校验；后者是定时任务无请求上下文时按平台租户兜底（benign）。
4. **captcha/enabled 返回 403**：auth 自身返回（非网关拦截），登录页表单仍能正常渲染登录，未阻断走查。待查是否白名单/权限配置问题。
